# Keyframes, transcription and the text agents read

Read this before changing `src/keyframes.rs`, `src/transcribe.rs`, `src/deepgram.rs`, `src/hex.rs`, `src/command_transcriber.rs`, `src/sketch.rs` (`summary.md`) or `src/render.rs` (frames and the contact sheet).

## Images and text

- **Images (`frames/*.png` and `contact-sheet.png`)**: Keep images purely visual. Each keyframe shows the screenshot, active red tldraw stroke(s) for that moment, a subtle click mark (thin translucent ring and small dot, no fill, so the clicked thing stays readable; phone swipes are a thin translucent trail), and the keyframe's number alone (no `#`, no time; `summary.md` pairs each `[#N · M:SS]` with its words) in bold black on a small white rounded square with a thin dark ring, inset 5 px from the top-left corner and dodging to top-right when top-left has ink, a click or the cursor. The chip is drawn at one size on every contact-sheet tile, about 24 px with its ring: blind reading tests found 20 px failed when the sheet was shown at half size, a bare digit was read as screenshot text, and `#6` was read as `8`. `contact-sheet.png` packs frames in time order (left→right, top→bottom) into aspect-ratio-justified rows separated by tight 6 px gutters on a dark canvas (no card borders or rounded frame masks, capped at 1600 px long edge / ~1.56 MP) with no rasterized transcript headers or caption boxes.
- **Text (`summary.md` & Clipboard)**: Put the transcript, `[#N · M:SS]` keyframe index, and absolute file paths (`Contact sheet:`, `frames/frame-XX.png`, `Video:`, `Bundle:`) in plain text (`NSPasteboardTypeString`) without repeating the transcript multiple times, so `⌘V` pastes cleanly into any terminal (Ghostty / OpenCode TUI) or GUI composer (OpenCode Desktop).

## Transcription (`src/transcribe.rs`, `src/deepgram.rs`, `src/hex.rs`, `src/command_transcriber.rs`)

Deepgram nova-3 by default on macOS (`src/deepgram.rs`, `"transcriber": "deepgram"`); Apple SpeechAnalyzer by default elsewhere and as the fallback (measured word times). Deepgram gets the recording's `audio.wav` through `/usr/bin/curl --config -`: the key (`DEEPGRAM_API_KEY` from the environment, else `~/.config/codecaine/env`) goes only on curl's stdin, never in argv, a log or an error, and the HTTP code is read apart from the body. It asks for `model=nova-3&smart_format=true&punctuate=true&utterances=true` and `language=<hexLanguage>` (`auto` sends `detect_language=true`). `alternatives[0].transcript` is the text, each `punctuated_word` with its `start`/`end` seconds is a word in ms, and each utterance is a segment: `source: "deepgram:nova-3"`, never `estimated`. No key, no answer within 120 s, a non-200 answer, an empty result or an unreadable one means Apple for that recording; the fixed reason is logged and kept (`transcribe::deepgram_fallback`) for Settings › Recording to show until the next Deepgram success. With Deepgram preferred, the `liveTranscribe` experiment does not stream (live words still do). `scrawl reprocess B --out O --transcriber deepgram` tries it on a bundle. `"transcriber": "hex"` + `"hexModel"` in `~/.config/scrawl/config.json` (Settings › Recording, `scrawl hex status`, `--transcriber` on `reprocess`/`import`) uses Hex's local API v2 (discovery file `local-api.json` in Hex's `hex` data folder, else the older `voice-control` one when that's missing or doesn't answer; bearer token, never logged) only when Hex answers `/health` and has a ready model (`installed && verified`; Scrawl never downloads). Hex gives text only, so each speech island (`audio::speech_islands`, clips merged to ≤ 24) is transcribed on its own and its words are spread over it by length: `source: "hex:<model>"`, `estimated: true`, which `keyframes.rs` reads to skip spoken cues. Any Hex failure falls back to Apple for that recording; Hex absent falls back silently (logged once). `"transcriber": "command"` (`src/command_transcriber.rs`) runs the argv in `"transcribeCommand"` (no shell, own process group, wall-clock limit, 8 MiB stdout cap) and reads one versioned JSON transcript: `source: "command:<name>"`; any failure means Apple for that recording (Hex never tried; a missing or malformed command is logged once, like Hex being away), and nothing the program says or is given reaches the log. It gets no language from Scrawl: `appleLocale` is Apple's, and the user's argv carries the model's. Its keys are read on their own (`Program::load_from`), never through `handoff::Config`. Settings reads `hex::cached_status` (a background poller), never the network.

Hex requests use `"hexLanguage"` (Settings › Recording › Hex language), default `en`.
The field accepts a language code or `auto`, trims/lowercases it, and saves on Return/Apply;
blank resets to `en`. Scrawl validates URL-safe code syntax only, leaving supported languages
to Hex. The selection is read once per recording and reused for all speech islands/retries.
It does not inherit Hex's dictation settings. An unsupported code follows the existing
Hex-failure fallback. Models may ignore language hints (e.g. Parakeet v3).

Apple's model (`src/speech_model.rs`, `scrawl-helper speech-model [--install]`) is SpeechTranscriber where the Mac supports it, else DictationTranscriber (VMs and Macs where `SpeechTranscriber.isAvailable` is false). Its language is `"appleLocale"` (Settings › Recording › Language, e.g. `"zh-TW"`; absent or `auto` is Automatic: the user's locale, the nearest supported one, or en-US). Rust passes it as `--locale ID` to the helper's `transcribe`, `transcribe-stream` and `speech-model`, which match it by `Locale.language.maximalIdentifier` (`zh_TW`, `zh-TW` and `zh-Hant-TW` match, `zh-Hans-TW` doesn't); an unsupported one gets the Automatic pick. `speech-model` lines carry `locales`, the supported ids, for the Settings menu, which marks a saved language this Mac lacks "(not available)" and names the one used. `appleLocale` is Apple's alone: Hex has `hexLanguage`.

Each app reserves the model for itself through `AssetInventory` (attributed to `dev.kitlangton.scrawl.helper`), one slot per language (at the limit the helper releases languages Scrawl no longer uses), and a fresh Mac doesn't have it, so the app checks and installs it in the background at launch (not when the transcriber is Hex) and retries a failed install. Changing the language (`speech_model::restart`) bumps the worker's generation: the superseded helper is killed, its late lines are ignored, and the new language is checked. Onboarding's Microphone row, Try it and Settings › Recording show the download. `transcribe` never downloads for long: without a model it returns `missing` (`downloading`, `unsupported`, `failed`), the summary gets a `No transcript: …` line (`TranscriptData::missing`), and a retryable bundle gets `.transcript-pending` and is transcribed again in place, `scrawl.json` and `summary.md` rewritten, when the model arrives (`scrawl retranscribe <bundle>` by hand). On macOS 15 there's no SpeechAnalyzer or `AssetInventory`: the model is SFSpeechRecognizer's on-device Dictation model (`Recognizer` in `helper/Media.swift`), SFSpeechRecognizer needs the Speech Recognition permission, which onboarding asks for as an optional fourth row (`Permission::SpeechRecognition`, shown only when `scrawl-helper permissions` reports it, i.e. before macOS 26; also in Settings › Permissions). `speech-model` never prompts: without the permission its status is `permission` (`State::NeedsPermission`, no retries; a fresh grant seen by `read_grants` starts the check again), and otherwise it checks the model by recognizing half a second of silence (`supportsOnDeviceRecognition` can be true before Dictation's model is downloaded), a failed check being `failed` with an `error` that says to turn on Dictation. Recognition is on device only. `transcribe` never prompts either; without the permission it returns `missing: permission`, without the model `missing: dictation`, and both bundles get `.transcript-pending`.

## Keyframe selection (`src/keyframes.rs`)

- Only cut keyframes on real visual or input events (`Mark` strokes drawn while holding `⇧`, flags, `Click`/`Drag` inside the capture target or phone taps/swipes, `Laser` points, or settled `SceneChange` transitions)—never cut extra keyframes on speech pauses alone over a static screen.
- The one speech exception is a spoken cue with measured word timings (SpeechAnalyzer; never a Hex transcript, whose times are `estimated`): "now", "here", "look", "watch" snap to a transition that starts within −0.3 s…+1.2 s of the word, else take the frame 150 ms after it. A cue keyframe is dropped unless its image differs (scene diff ≥ 0.03) from every keyframe already chosen, so speech over an unchanged screen still yields one frame. Demonstratives and "see"/"there" are weak (they rank with ordinary scene changes) because they are usually filler.
- Budget (`keyframe_budget`): 6 up to 40 s, then one more per 20 s, at most 12 (each image costs a reading model ~1–1.5k tokens). Ordinary events fill only the first 6; the rest are for marks and coverage.
- Marks are never dropped. Marks drawn on the same screen share one keyframe at the last of them, which draws all their ink (`mark.frame` names it; `markId` is the first): the screen counts as the same while the luma grid around their ink, padded by 8%, changed in under 5% of its cells. A group closes at a click or drag, past 20 s, or past 12 strokes. Groups beyond the budget merge with a neighbour: same-screen pairs with the least ink first, else the most alike screens. Flags stay on their own. No other keyframe cuts into a multi-mark group's span. Auto-crop gives a group's ink to its keyframe's crop alone (`Input::pin_ink`).
- Coverage: after marks, a stretch longer than 100 words or 35 s gets a frame from inside it when one qualifies (a click, laser, settled scene change or novel cue); the lead-in before the first keyframe is its own stretch. Speech over an unchanged screen still yields one frame.
- Text per keyframe: each keyframe owns the words from the start of the clause in progress at its anchor (action start, transition start, or cue word) until the next keyframe's start. Clauses break at clause punctuation, recognizer segment starts, or a ≥1.5 s pause. Words before the first keyframe belong to it.
- Mark shapes (`sketch::marks_of`, measured in pixels): a stroke is a circle when it ends near where it began, is longer than twice its box's long side and fills a third of its box, whose short side is over 0.42 of its long side; flatter loops, to 5:1 (a wide cell or a line of text gets a flat loop), also count when they close well within their short side and go round at most about three times, so a flat C or a scribble over text doesn't. A loop like that which is most of a stroke with a lead-in, tail or overshoot is a circle too. Either way the mark's `box_norm` is the loop alone, without the lead-in or tail (a stroke gone round more than once keeps its whole box). In strokes longer than 512 points a loop's ends are tried at every nth point only, but each stretch is still judged by the whole recorded path's length and area. A straight stroke is a line or underline. An arrow is a line with one or two short strokes near one end (the head), or one stroke whose straight shaft turns back at the tip into one or two straight barbs and whose head reaches both sides of the shaft (two barbs, or one that runs on across it); `from` is the shaft's start and `to` the tip. An underline whose end hooks back to one side, ticks, V's, zigzags, scribbles and C-shaped arcs stay plain marks.

## App state (`appState`: `src/agent_context.rs`, `src/ax.rs`, `src/appshot.rs`, `src/privacy.rs`)

On by default on macOS and off elsewhere: Settings › Recording › For agents › **Save app state**, or `"appState": true|false` in `config.json` (`handoff::app_state`). It was the `agentContext` experiment: an older `"experiments": {"agentContext": …}` value still counts while `appState` is not set, and `--experiment agentContext` on `scrawl reprocess` or `scrawl inspect` forces it on for that run. Tests see it off unless they call `handoff::enable_experiment`. With it on, `sketch::summary_markdown` hands each keyframe to `agent_context::keyframe_texts`, which recovers the keyframe's timed words from its `said` and breaks them up by what happened while they were said: marks, clicks, drags, scrolls, shortcuts, and repeats of one item within 3 s folded into `×N` (`pressed ⌘T ×3`, `clicked ×4`), ordinary windows opening and closing (layer 0, by app name; titles never leave `scrawl.json`), app switches by app name, ScrawlKit app events and context changes. The text never gives raw coordinates (the images show where): a place is written only when something names it. A mark is its shape, then what it was drawn on when `Mark.on` names it, then its stroke count when more than one (`✎② 0:19 circled button “Window” (2 strokes)`, `✎ 0:05 marked`); a click is `clicked`, plus its role and label when known (`clicked button “Area”`); a point is shown only with a label. An unnamed drag shorter than 0.15 of the screen is left out; a longer one is its direction (`dragged right`), and a named one names its target, `scrubbed` for a slider, scroll bar, scrubber, timeline or progress bar (`scrubbed slider “Playback”`). Drags of one thing less than 3 s apart are one line (`dragged back and forth ×2`), and a drag the dev page already reported as a video scrub is left to that report. Speech before the first item stays on the bullet line; each mark, or run of events with no speech between them, starts an indented line followed by the words said until the next one. An item's place in the speech moves back to the start of its clause if that began within 3 s, else forward past the clause's last word if it ends within 1.2 s, so a clause isn't cut in half. Events belong to the keyframe whose stretch they fall in (a stretch starts at the keyframe's first word, first mark, own moment or, for a click keyframe, its click up to 1.5 s before); marks always belong to their own keyframe. Without word times (a segment-only transcript) the speech stays whole and the items follow it.

When a keyframe draws two or more marks they are numbered ①②③ in drawing order (`sketch::marks_on`) in the text and `scrawl.json`, never on the image: frames, contact sheets and exports show only the red ink, so nothing covers the screen. Single-mark keyframes stay unnumbered. Pins are the one exception: a pin is drawn as a red disc in a white ring with its own number in white (`render::draw_pin`) on frames, contact sheets (so in the Review window too) and exports (`helper/Export.swift`), and live while recording (`laser_overlay`, which samples the label `render::pin_label_coverage` draws). That number is the pin's `pin` in `scrawl.json` and its `pin N` in `summary.md`: 1, 2, 3 in the order the pins were dropped in the recording, whatever keyframe they land on. `agent_context::mark_entries` / `find_mark` look marks up by those numbers: `scrawl inspect --marks [--json]` lists each mark's keyframe, number, time, shape, what it was drawn on and id (`#2 ✎② 0:09 marked (2 strokes) · m2`), and `scrawl zoom --mark 2 [--frame 2]` (or `--mark m2`) zooms on that mark, centred on its time span (at least `--span`, the whole mark plus half a second either side), cropped like its keyframe, with its whole ink drawn from the moment it starts. A number on several keyframes needs `--frame`; numbers shown as ①② win over single marks.

A scene-change keyframe says `[changed: the whole screen]` when its `autocrop.changes` boxes, merged when they touch, include one covering 90%. Smaller changed regions have nothing to name them yet, so the text leaves them to the image. A keyframe with no speech or items falls back to its own description without positions (`scene changed`).

With app state on when a Mac capture starts (not the iPhone mirror, and only with Accessibility granted), `crate::ax` looks up what each click and ⇧ stroke lands on in the Accessibility tree: the element at the mouse-down point, and for a stroke the middle of its box (just above a flat stroke, since an underline sits under what it marks). `ax::lookup` first reads the roles from that element up to its window. An input on that path (a text field, text area, combo box, search field or secure field) is what the point is on, whatever text sits inside it, and it is named by its title, description or placeholder: its value is never asked for. Otherwise a click on a button's text or icon is named by the button (up to two parents). It reads the role description, a label (title, description, the value only of static text, placeholder), `AXIdentifier` or `AXDOMIdentifier`, and the file name of the window's `AXDocument` without its query; never a window title, and every string cut to one line of 60 characters. When the path to the window can't be read within the budget, or the app is a password manager, only the role is kept (see **What app state never keeps** below). Lookups run one at a time on the `scrawl-ax` thread with a 0.1 s messaging timeout and a 250 ms budget each; lookups that hit Scrawl's own windows retry on the app whose window is under the point. `finish_session` waits up to 400 ms for running lookups and puts the results on `Click.role` / `Click.label` (`“New Tab” #tab-new in main.rs`), `Drag.label` and `Stroke.on` (`button “Area”`, which `Mark.on` and the mark's description pick up). Results of an earlier capture are dropped (`Prober::begin`).

Dev pages that load `/sdk.js` add what only the page knows (`src/page.rs`, `src/sdk.js`). With app state on, `/web/register` answers `"context": true` to loopback pages, and the script then hooks in once: the element under each `pointerdown` and under mouse moves with the draw modifier alone held (every 250 ms; `/web/register` names the modifier as `"draw"`, read from `shortcuts.draw` on each registration, so a change in Settings › Shortcuts reaches an open page within its 30 s heartbeat) as tag, id, two classes, a label (`aria-label`, `title`, `alt`, `data-testid`, else up to 60 characters of text, without the text of any field inside it), or for a field its name (those attributes, else the placeholder or `name`, not for a password field) and never its text or value. A field is an input, a text area, a select, an editable element or an element with `textbox`, `searchbox`, `combobox` or `spinbutton` anywhere in its `role` list, in any case, and it is looked for from the element the pointer is on, before a label or button around it stands in for that element; the page marks it `field`, and `page::sanitize` drops any text sent for a field or for an `input`, `textarea` or `select` tag, and the component and source `file:line` from React's fiber (`_debugSource`, or the first project frame of `_debugStack`) or a locator attribute (`data-source-loc`, `data-inspector-relative-path`/`-line`, `data-sentry-component`/`-source-file`); `<video>`/`<audio>` seeks, plays and pauses (file name, time, duration); `console.error`, uncaught errors and unhandled rejections (message and first project frame); and fetch/XHR requests that fail or answer 400+ (method, path without query, status, duration; no bodies, headers or cookies). It batches them to `POST /web/context`, which takes loopback pages from this Mac only, token or not, and drops them when app state is off. The app keeps 3 minutes per tab (300 events, 16 tabs) and cuts every string again, taking the query and fragment off any URL in it (`privacy::clip`). When a capture finishes (`finish_session`, not the iPhone mirror), `page::apply` takes the window's events from tabs that were clicked, marked or focused then: a page click within 400 ms of a Mac click or drag replaces its label (`<button.tab-new> “New tab” in BrowserHeader (src/BrowserHeader.tsx:88)`), the most common element under a stroke's ⇧ moves becomes its `on`, and errors, failed requests and video playback become app events (`console error: …`, `GET /api/tabs → 404`, `video clips.mp4 scrubbed to 0:04 / 0:11`, a scrub's seeks folded into its last). The app state summary shows a Mac capture's app events without the `app:` prefix.

### App shots (`src/appshot.rs`, macOS)

An app shot is the state of the window a keyframe shows: its app, bundle id, window title, URL and a text outline of its Accessibility tree, one element per line, indented by depth (`button "Save" #save`, `text field "Name"`, `static text "Open the settings…"`). The pasted text stays short: when a capture has shots, `summary.md` and the clipboard get one line, `App shots: scrawl appshot <the capture's id> --frame N (N is the keyframe number)`, and the agent runs it when it wants more than the picture.

- **Taking them.** One walker thread (`scrawl-appshot`, `appshot::Walker`) takes a shot when the capture starts, when the top window or its title changes (the window log calls it, Screen and Area), 300 ms after a click or a mark, and when a candidate frame differs from the one before by more than the scene threshold (`keyframes::Thumbnail::is_scene_change`, 0.08, at most once per 2 s). Its queue holds one request and the latest wins. A paused recording takes none, and resuming takes one at once.
- **Which window.** Screen and Area take `windows::top_raw_window` of the live window list, the same rule as `windows::top_window` on the log. A Window capture takes its window and takes nothing once the window server no longer lists it. The Accessibility window is the one of the app's `AXWindows` that gives the captured window's id (`appshot::find_window`; the id is the window server's `CGWindowID`, read with the private `_AXUIElementGetWindow` that window managers use). Nothing else proves it: a window's place and title do not, since the captured window may have moved or closed after the window server was asked and another window of the app may be at its old place. When a window gives no id, place and title count only if it is the app's one window: it must be at the window server's bounds within 2 pt, and its `AXTitle` must be the window server's title, begin with it or the other way round (a browser's Accessibility title is the window's title and more), or be missing. In every other case no shot is taken and the log says why once per window (`App shot skipped: …`): the app's focused window is never read in its place, so a shot's window id is always the window its tree is of. `cargo test appshot_live_finds -- --ignored --nocapture` prints, for each window on screen, whether it is found and the id, place and size each of its app's windows gives. Annotator's own windows are never read.
- **Limits.** Every element gets a 0.25 s messaging timeout before it is asked anything, and one walk has 1.5 s, 12 levels, 1,500 nodes and 64 KB of outline. The 1.5 s and the capture's word that it dropped the shot (finish, cancel, pause) are checked before every question, from the first: reading the window list and finding the Accessibility window (`find_window`) stop on them too and then take no shot, while a tree that runs out of time keeps what it read. `truncated` names what cut it: `depth`, `nodes`, `bytes` or `timeout`. A frozen app costs the capture's finish at most 400 ms: `Walker::finish` waits that long for the walk in flight and then drops it, and `cancel` drops it at once. A walk that ends late never lands in the next capture (it is checked against the capture's generation under the lock that `finish` takes).
- **Electron.** An Electron app (one with `Electron Framework.framework` in its bundle) builds no Accessibility tree until asked. When its `AXManualAccessibility` reads false, Annotator sets it, skips that first, empty tree, and lets the next trigger read the real one; when the attribute can't be read, the app is left alone. Annotator sets it back when the capture finishes or is cancelled, and only for apps where it set it. If Annotator crashes mid-capture the app keeps its tree on until it restarts, which costs that app some speed and nothing else. `AXEnhancedUserInterface` is never set: it changes how apps lay out and animate.
- **Storing them.** Each new state (by the hash of app, bundle id, window id, title, URL and tree) is written to `appshots/.spool/` in the bundle folder when it is taken, so none is held in memory; only when each was seen is. The file is written outside the lock that `finish` and `cancel` take the capture with (`Shared::land`: the spool plans the write under the lock, the walker writes, then the shot is noted under the lock), so a disk that stalls costs `finish` no more than its 400 ms and `cancel` nothing; a shot whose capture ended during the write is dropped with its file. Past 32 MB a capture takes no new state and its timeline says `capped`. At finish, `Shots::store` turns the spool into `appshots/shot-NN.json` and `appshots/timeline.json` (one entry per time a shot was seen: `t`, the shot's file, window id, pid, bundle id, app, title, frame and `tookMs`; plus `scenes` and `capped`), with the pauses cut out like every other timeline (`Shots::cut`). A shot whose walk a pause fell in (`Cuts::overlaps` over `t` to `t + tookMs`) is dropped there: a walk that began before a pause and ended after it read the window as it was after, and is not kept under its time before. Cancelling deletes the spool with the bundle, `scrawl recover` deletes one it finds, and at launch the app deletes the spool of any capture folder without a `scrawl.json` (`appshot::sweep_spools`).
- **Matching.** `appshot::match_keyframes` gives each keyframe a shot file (`Keyframe.appshot` in `scrawl.json`). The window a keyframe expects is the top window of the last window-log snapshot at or before it (the first snapshot for an earlier keyframe), or the capture's window for a Window capture. Only a shot of that window counts, taken while the capture stayed on it and within 3 s of the keyframe: the nearest one, except that a shot from before the last click, mark or picture change before the keyframe loses to any shot from after it. A shot without a window id goes by bundle id when both have one, else by app name. A keyframe with no such shot gets none, never another window's.
- **Reading them.** `scrawl appshot [BUNDLE] [--frame N] [--json]` (`appshot::report`; BUNDLE is an id, a path or `latest`). Without `--frame` it lists each keyframe's app, window, URL, how far from the keyframe its shot was taken, and its node count, never the tree. With `--frame N` it prints that keyframe's header and outline. A capture without shots prints `no app shots in this capture` and exits 0; a keyframe without one names the window it expected; `--frame` out of range names the range and exits 2.
- **Rebuilding.** `scrawl reprocess` takes the older bundle's `appshots/` along and matches the new keyframes to it. `scrawl recover` has no shots to pass on.

### What app state never keeps (`src/privacy.rs`)

Everything app state stores goes through `src/privacy.rs` first: the click and mark lookups, the window log's titles, the capture's window title (`target.windowTitle`, which the summary's first line prints), dev-page events, and app shots. So it holds for `scrawl.json`, `summary.md`, the clipboard, `appshots/` and what `scrawl appshot` prints.

- **No typed value.** A value is kept only for static text. A text field, text area, combo box, search field or secure field keeps its role and its names, and its value is never asked for (`privacy::read` is the only place that reads `AXValue`). Nothing under an input is read either: text under an input is that input's value.
- **No URL query.** Every string is one line of at most 200 characters (60 for a click or mark label), and a URL inside it loses its query, its fragment and any `user:password@`, with a scheme or without one (`reset.html?…`, `a.dev/callback#…`). Prose keeps its `?` and `#` ("why?", "#42").
- **Nothing from a password manager.** 1Password, Bitwarden, Keychain Access, Passwords and LastPass (`privacy::SENSITIVE_APPS`, exact bundle ids) give their app name only: no title, URL, tree, label, identifier or document. They are never sent an Accessibility message.
- **No tree from a browser's own pages** (`chrome://`, `edge://`, `about:`, `safari-resource:`).
- **Kept on purpose:** text an app shows as static text, such as a code in a message. It is on the keyframe image too.

**What stays.** `appshots/` is small text, so retention leaves it alone: it stays with the capture after the video and audio are cleaned, like `frames/` and `scrawl.json` (`handoff::HEAVY_MEDIA` lists what goes), and it travels with the bundle when a capture is synced to another Mac. Turn **Save app state** off to stop saving it; delete a capture to remove what it saved.

**Proving it.** `cargo test privacy` and `cargo test appshot` run the lookups and the walker over a fake tree (`privacy::fake::FakeTree`) that records every attribute asked for, with a marker in a typed value, a password, a URL query, a window title and each dev-page string. `cargo test sdk_page -- --ignored` runs the real `sdk.js` over `Tests/fixtures/appshot-secret.html` in headless Google Chrome, with markers typed into every field, and checks what the page posts and what the app keeps. For the real thing, open `Tests/fixtures/appshot-secret.html?token=SECRET-MARKER-URL` in a browser, type `SECRET-MARKER-INPUT` into Name, click Save, record it, and `grep -r SECRET-MARKER` the capture's folder: nothing.

## Experiment `liveTranscribe` (`src/live_transcribe.rs`, `helper/LiveTranscribe.swift`)

Off by default (see Experiments in `AGENTS.md`). With it on and Apple Speech the transcriber, `AudioRecorder::start` also starts `scrawl-helper transcribe-stream` (one SpeechAnalyzer, finalized results only; it never downloads a model, so one that isn't installed fails at once) and a thread that feeds it the recorder's 16 kHz buffer as `audio::pcm16` every 160 ms. `RecordedAudio.live` carries it to `transcribe::transcribe`, which sends the samples it hasn't had from the finished WAV, closes its input and waits up to 6 s for the tail; the helper must report exactly the WAV's sample count. Word times are therefore the WAV's own, and match one SpeechAnalyzer pass over `audio.wav` word for word and millisecond for millisecond (the batch path splits recordings over 22 s at silences and transcribes the pieces in parallel, so long recordings can differ from it at the cuts). Any failure is logged (`Live transcription failed, …`) and the WAV is transcribed as before; Hex, iPhone and imported recordings never stream. With Show live audio on (`"liveAudio"`, `docs/onboarding-and-settings.md`) the same stream also reports guesses (`--volatile`, ignored by `finish`) to show the words in the capsule. `scrawl reprocess B --out O --bench 1 --live-speed 1` replays a bundle's audio into it in real time and logs `Live transcription: N words, … tail N ms` and the finish timings.

## Experiment `clipboardImage` (`src/handoff.rs`, `src/win/clipboard.rs`)

Off by default; Windows only. A finished capture (and `scrawl send` to the clipboard) normally copies `summary.md`'s text alone, so pressing Ctrl+V yourself drops the contact sheet; only the Paste chip and the paste shortcut paste the image first. With it on, `copy_bundle_to_clipboard` puts `contact-sheet.png` (`PNG` and `CF_DIBV5`) and the text on the clipboard together, so one Ctrl+V attaches the image and inserts the text in a browser or Electron composer (checked in the Claude desktop app) and pastes just the text in a terminal. If the contact sheet can't be read, the text is copied alone.

To compare a summary experiment on real captures, `scripts/agent-eval.sh [--experiment NAME] [--out DIR] [bundle…]` reprocesses each bundle with and without it (Kit's own `experiments` removed from the baseline's config) and writes `before.md`, `after.md`, both contact sheets and frames per bundle, and an `index.md`, by default to `~/code/home/artifacts/scrawl-context/`. Both summaries come from the baseline run's transcript. What a capture recorded live (Accessibility lookups, page events) is kept as recorded, so those only show on captures made with the experiment on.
